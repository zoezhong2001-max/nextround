# NextRound 产品原则

本文记录经长期实践确认的产品方向。它是设计与验收的基准，各项能力的实现进度以仓库实际状态为准。

## 定位与边界

NextRound 是面向泛互联网求职的 Agent 工作台。业务能力来自可替换的领域 skill（首个实现：产品经理求职），未来通过替换 skill 扩展更多岗位方向。个人资料、招聘记录与凭据保存在私有数据区，不进入公开仓库。

用户在外部 Agent 宿主中表达目标、补充事实和讨论；Agent 在任务范围内读取资料、分析并整理成果；工作台用于浏览、核对和人工编辑这些成果。工作台不内置聊天页或 Agent 对话栏。

## Agent 与工作台的职责

- Agent 决定如何分析、读取哪些必要资料、调用哪些工具及如何组织工作；根据真实材料和反馈调整方法。
- 工作台负责资料和成果的归属、结构化呈现、编辑、版本、来源、执行状态及结果反馈。
- Skill 提供领域方法、质量要求和事实边界。不用固定关键词路由、固定题量或机械填模板替代 Agent 的判断。
- 结构约束信息归属，不限制分析深度。原始问答、确认事实、推断、建议与复盘后示范保持区分；内容按实际任务组织，有实质信息才创建板块。
- 以持续协作的成果为核心对象：完成任务应留下可查看、可修改、可追溯、可继续迭代的对象，而非只有一条聊天回复。

## 用户与成果协作

- 每轮成果可以被提意见、继续讨论或直接编辑。
- 反馈可定位到一句话、一个问题组、一段经历、一份准备稿或整个成果。
- Agent 修改前读取最新对象，优先提出目标明确的局部修改；展示前后差异，支持接受、拒绝、自行编辑和继续迭代。
- 迭代同一成果时保留对象身份、历史版本和引用关系；不每次重新生成无关联长文。
- 原始逐字稿与历史实际问答保持可追溯；可持续修改的是分析、建议、示范及经核实的更正，不把建议改写成历史事实。

## 自主执行与可控性

- 读取、分析、起草和用户明确要求的可恢复动作尽量自主完成；不每步都弹确认。
- 对已有成果的修改保留差异和版本；个人事实与流程结果有用户或可信来源依据。
- 成功以真实工具回执为准。执行记录在对话或任务记录展示，不混入正式成果正文。
- 支持停止、失败续做和信息补充；已成功步骤保留，续做不重复创建阶段或成果。
- 按需读取上下文，避免把整套资料库默认塞入每轮对话。

## 信息架构

固定导航四区：**仪表盘、岗位流程、面试复盘、个人资产**。对话与执行由外部 Agent 宿主承担，工作台主区域用于阅读和人工编辑。求职批次位于岗位之上，历史总览由结构化流程生成，不作为普通材料要求用户勾选。

个人资产以可核对的档案事实与经历为核心；母版引用这些事实，岗位保存定向简历和实际投递快照。单场复盘完整保留逐题实际问答，跨场问题族引用各次回答与建议。外部文档是来源，不决定页面结构。不同岗位即使通过 HR 转推关联，也拥有独立的岗位理解、场次、阶段与结果；招聘方向说明不自动变成多个岗位。

## 人工修改的读取约定

人工编辑保存到私有数据库的修改日志（`rebuildEdits`），读取接口返回原始整理资料与人工修改合并后的当前内容、版本标记和修改历史。Agent 继续整理前必须读取该合并视图，不能仅凭历史快照判断最新事实；重新生成基础资料时人工修改优先保留。

原始问题和实际回答引用不可通过内容编辑改写。Agent 不得把自己生成的分析通过人工编辑接口冒充用户确认；涉及人工已改字段的新建议，应先提出具体变更再更新。

## 成效衡量

以任务完成质量、事实可靠性、修改可控性及减少资料搬运和页面切换衡量，不以模板数量或工具数量衡量。
