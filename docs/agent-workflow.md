# NextRound 内部 Agent 工作流

## 本次实现范围

对话通过本机 Codex app-server 的动态工具协议调用工作台能力。当前版本完成工作台内部的读取、流程更新、复盘、准备、经历草稿、练习和缺信息续做。公司信息联网检索、Computer use 和岗位 skill 插件分流不在本次实现中；业务规则仍来自本机 pm-interview skill。

用户可以从独立对话发起任务，也可以从岗位、复盘、文档、经历页打开带当前对象的侧边对话。原始资料不因任务测试或工具调用而重新导入、重写或迁移。

## 调用与执行

1. TaskRunner 在认证后创建本地会话、保存用户消息和任务。全局启动锁在异步认证前获取，避免同时运行两项任务。
2. 首次使用新版 Agent 的旧会话保留本地历史，以最近对话和资料索引建立带工具的新 Codex 线程；后续恢复同一线程。
3. CodexBridge 在 thread/start 注册动态工具，在 item/tool/call 中按线程和轮次路由。工具调用串行处理，未知或失效任务不能获得执行回执。
4. WorkbenchTools 校验工具参数、岗位、阶段、资料读取版本和业务规则。只读材料按页获取；录音不自动处理。
5. 写入与任务步骤回执处于同一 SQLite 事务。成功后返回实际 ID、标题和路由，模型基于回执继续。
6. 用户看到独立成果卡片、可折叠执行记录和必要待补问题。正式文档不承载执行日志。

接口根据官方文档及本机生成的 JSON Schema 实现：https://learn.chatgpt.com/docs/app-server 。

## 内部工具

- context：读取所选岗位及材料索引；未选岗位时读取岗位目录。
- bind：从用户明确提及的唯一岗位绑定当前通用会话；有歧义时要求选择。
- read：分页读取当前岗位资料或个人资产，记录内容指纹与读取范围。
- rules：按需读取本地 skill 的能力模块。
- progress：使用用户原话作为结果依据，复用事务式进度更新。推测不能当成已确认结果，旧阶段不能回退当前阶段。
- save_review：完整读取逐字稿后保存逐题复盘，逐题校验引用；同场已有复盘保留原问答。
- save_document：独立保存当前阶段准备，或关联既有资产的经历/简历草稿。已有可修改准备保存版本；冻结准备不覆盖。
- add_practice：把有明确来源的改进加入当前岗位阶段。
- need_input：保存一个决定性问题，用户补充后继续原任务。

## 恢复和确认

任务状态：running、waiting-input、completed、failed。

- waiting-input：保留问题、已完成步骤与成果，用户在同一对话补充后继续原任务。
- failed：保留成果，使用“继续未完成部分”恢复原任务；不会因为重试另建一个复盘或流程事件。
- 停止：阻止后续工具写入，保留已提交结果。
- 服务重启：将运行中任务标记为未完成，后续恢复。
- 经历修改：Agent 只生成关联原资产的草稿；用户对照原文和草稿、填写核对依据后确认。保存时核对原资产内容指纹，并保留版本；并发修改产生冲突时不覆盖。

重试去重覆盖同一任务的已成功写入；不同任务的进度事件仍由业务层去重。同场复盘默认复用已有页；普通“重新生成”不会覆盖历史原话。新一轮准备与上一轮复盘保持独立。

## 验证

`npm test`：使用隔离的临时数据库和模拟模型回执，覆盖跨岗位、原话校验、分页读取、流程去重、事务回滚、失败续做、缺信息续做和事实版本保护。

`npm run build`：前端构建。

`node scripts/check-agent-tools.mjs`：真实模型最小工具往返测试，返回只由工具生成的随机回执。

`node scripts/check-agent-workflow.mjs`：用临时数据库、合成逐字稿、真实模型与本地 skill，验证复盘 → 进度 → 二面准备全过程。这两项显式检查会使用账户额度，不进入自动单元测试，也不写入真实面试资料库。
