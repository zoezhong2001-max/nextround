# 私有知识库格式校准

只在用户要求按新版 skill 整理、迁移或校准既有 Hub 时读取。本模式修正信息架构和显示方式，不重新执行历史任务。

## 边界

- 先读取目标页最新版本和实际链接，再制定最小修改范围。
- 保留既有事实、分析结论、原始问答、来源和冻结产物；不得借格式校准重新生成准备或复盘。
- 可以重排目录、稳定页和索引，删除流程说明、迁移记录、测试文字、空模板与裸露内部状态码。
- 历史上把 Review 与下一阶段准备合并在一页的文档默认原样保留，并在目录中标为“历史合并页”；只有用户明确要求且拆分不会改写内容时才迁移。
- 不为补齐新版结构机械创建空页。只有当前仍在推进的流程缺少 Process 或索引，且用户把它纳入本次校准范围时，才建立最小页面。

## Hub 校准

Hub 是导航首页，不是 Current Plan 的副本。可以使用分组入口、卡片、按钮、自动子页面列表或真正引用同一来源的同步模块来改善可读性，但必须遵守：

- `PM_INTERVIEW_HUB_V1` 标记保留。
- 当前状态、活跃流程和行动仍以 Current Plan 为唯一事实源。
- 连接器能够稳定创建和回查同步引用时，才把 Current Plan 的现有模块嵌入 Hub；不能建立真同步时，不复制活跃流程表。
- `90 Rule Promotion Queue` 与 `99 Inbox` 为按需区域：页面已存在时可放在次要入口；为空时不占用首页主视觉区。
- 不在首页展示维护方法、写回路由、测试过程、隐私发布规则或状态码。

## 写入与验收

1. 批量替换或删除前向用户说明页面和范围，并取得确认。
2. 优先局部修改；只有目录页或稳定页已被流程文字严重污染、且完整重构更安全时才覆盖正文。
3. Wiki 内页面存在知识库 URL 时，目录和导航优先使用知识库 URL；不要仅为换 URL 改写冻结正文。
4. 写后重新读取每个目标页，核对标题、链接、事实、状态、入口与冻结内容。
5. 对用户只报告实际更新、新建和未改动的范围，不把内部迁移清单写回飞书。
