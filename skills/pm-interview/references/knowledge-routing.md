# 知识路由

只在需要决定“读取什么、产出写到哪里、是否晋升为规则”时阅读本文件。

## 三类知识

### 事实

用户亲自确认、简历或可信原始材料能够支持的内容，例如任职时间、职责边界、产品方案、指标定义和结果。按字段归属维护：

- Profile 保存任职时间、角色、跨场景职责边界和会被简历/多张经历卡共同引用的高风险口径，并链接详细来源。
- Experience Card 保存单个项目的完整链路、实现机制、判断、指标字典和问答，是该项目细节的主记录。
- Process 只保存当前岗位事实、流程状态和岗位匹配摘要，不成为个人经历事实源。

面试复盘确认了新的项目事实时，先更新对应 Experience Card；若该事实会影响简历、其他经历卡或全局口径，同时更新 Profile 的高风险事实索引。两处都记录来源与确认时间，不能让旧 Profile 覆盖较新的项目事实。

### 答案

为了表达事实而组织的口述版本，包括自我介绍、STAR 故事、项目深挖答案和公司定制回答。

- 跨公司围绕同一经历复用：Experience Cards。
- 针对当前公司、岗位或轮次改写：当轮准备或专项答案文档，由 Process 提供链接。
- 简历成品：Resumes。

### 教训与规则

- 从某场面试得到、仍与用户背景相关的改进：可进入 Reusable Learnings 并标为“待验证”；至少两个独立流程支持且无关键反证后标为“已验证”。
- 可能对其他 PM 候选人也有价值：Rule Promotion Queue。
- 完成脱敏、验证和授权：才进入公开 skill 的 references、templates 或 SKILL.md。

## 写入优先级

一次任务可能更新多个位置，但必须各司其职：

1. 原始录音和用户提供的完整逐字稿进入 Inbox 或单场复盘的原始材料链接区，不改写、不重复转录。
2. 流程状态更新到 Process，以及 Current Plan 中的流程清单。
3. 公司定制答案更新到当轮准备或专项答案文档，并从 Process 链接；跨公司答案更新到 Experience Card。
4. 抽象教训更新到 Reusable Learnings。
5. 通用规则候选只进入 Rule Promotion Queue，不自动发布。

Reusable Learning 使用 `assets/templates/reusable-learning.md`：单场结论必须有明确的下一次验证计划并标为“待验证”；跨流程证据满足后再升级。Resume Version 使用 `assets/templates/resume-version.md`，只记录实际形成的投递或冻结版本。

## 复盘内容分流

- 本场原始问题、追问顺序、实际回答和时间戳：单场 Review。
- 本公司下一轮要使用的定制答案：当前 Process 的专项材料链接或当轮准备文档，不复制全篇 Review。
- 围绕同一经历、跨公司仍成立的事实模型和稳定讲法：Experience Card。
- 从多场面试反复出现的个人准备或表达规律：Reusable Learnings。
- 单场复盘后才想到的方案或补充思考：在 Review 中明确标记为“复盘后补充”；不得改写为当时已经做过或答过。

面试官/团队考察假设先留在当前 Process，附证据、范围、置信度、反例和验证计划；单场明确反馈与原始问题留在 Review。跨流程反复验证的个人应对规律才进入 Reusable Learnings，不能按公司标签直接晋升。

## 冲突处理

- Profile 与口述答案冲突：以已确认事实为准，标记答案待修订。
- 两份资料都声称是事实源：保留两者，展示差异并请用户确认；不要静默覆盖。
- 同一公司和岗位出现多个流程：依据年份或批次区分，避免混合。
- 无法确定归档位置：先保存为结构化草稿，并列出候选位置。
- 旧聊天、旧简历或旧答案与最新版事实源冲突：不得以聊天更近或表述更完整为由覆盖事实源；记录旧口径被哪条已确认事实替代。
